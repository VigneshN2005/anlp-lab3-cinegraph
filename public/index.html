RAG over the Neo4j Movies knowledge graph

Ask me anything about the 38 movies and 133 people in the Neo4j Movies graph. Each answer comes from a Cypher query, and you can open any answer to see how it was produced.

Knowledge graph schema

Property graph loaded from the official :play movies dataset.

Cypher query templates

Each question is mapped to one parameterised, read-only template. Parameters ($title, $name…) are filled by entity linking, never by string concatenation. That prevents Cypher injection.

Evaluation

38 labelled questions: direct, paraphrased, typo, partial-name, multi-turn, out-of-graph and 8 deliberately hard compositional questions.

How an answer is produced

  1. Entity linking. Movie titles and person names are matched against every node in the graph: exact, ignoring "The", first or last name alone, and fuzzy matching for typos.
  2. Dialogue state. "it", "he" or "she" resolve to the movie or person from the previous turn, so follow-up questions work.
  3. Intent → Cypher. Keyword rules plus the linked entity types select one of 17 Cypher templates and fill its parameters.
  4. Graph retrieval. The query runs on Neo4j AuraDB when it is configured. Otherwise it runs on an identical in-memory replica of the same dataset.
  5. Grounded generation. The LLM gets only the retrieved records and is told not to use outside knowledge. Without an API key, a template generator writes the answer from the same records.
  6. Open questions. If no template fits and Neo4j plus an LLM are available, the LLM writes a Cypher query. It is checked to be read-only before it runs.
